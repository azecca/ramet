A stack and its data for every branch.

ramet gives each git branch its own copy of your docker compose app: its own directory, its own containers on their own ports, and its own copy of every volume, from the database to the uploads. Mess up the data, then rewind it or throw it away.

$ ramet new feat-price

Get started Source on GitHub

One compose project, one set of volumes

A compose project has one set of ports and one set of volumes. Check out a second branch and it runs on the same stack and the same data: two branches cannot run side by side, and a migration or a bulk delete you regret has no way back.

An env for each branch

ramet calls each copy an env: a git worktree, a compose stack on ports of its own, and a btrfs snapshot of the data, which shares every block it has not changed.

  1. ramet new feat-price

    Creates the worktree, snapshots the data of the env you are in, and starts the stack on free ports. It takes seconds and almost no disk.

  2. ramet checkpoint before-migration

    Sets a return point on the data. ramet restore before-migration rewinds to it.

  3. ramet rm feat-price

    Removes the stack, the worktree and the data.

Your project is never modified. ramet adds no file to the repository and leaves compose.yml as it is, so a plain docker compose up keeps working.

Get started

Download, install, then create your first env 
arch=$(uname -m)
curl -fsSL "https://github.com/azecca/ramet/releases/latest/download/ramet-$arch-linux.tar.gz" | tar xz
"ramet-$arch-linux/install.sh"

cd ~/code/shop    # your compose project
ramet init
ramet new feat-price
  1. install.sh puts ramet in ~/.local/bin and prepares its data volume. It asks for your password once; no other ramet command uses sudo.
  2. ramet init, once per compose project, copies its docker volumes into ramet.
  3. ramet new clones the env you are in, and prints the new worktree and its ports.

You need

  • Linux
  • Docker Engine with Compose v2, and a user in the docker group
  • git 2.5 or later
  • btrfs-progs, but no btrfs partition: ramet keeps its data in an image file

Linux for now. ramet relies on btrfs snapshots and on docker running directly on the host. macOS and Windows are not supported yet.

On another architecture

Releases carry binaries for x86_64 and aarch64 (64-bit ARM). Anywhere else, build ramet from source. That takes git, a C compiler and Rust 1.98 or later, and install.sh says which one is missing before it starts.

Build from source, on Debian or Ubuntu 
sudo apt install git curl build-essential
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y    # Rust
git clone https://github.com/azecca/ramet
ramet/install.sh

Every day

ramet new <name>
Clone the current env.
ramet ls
List the envs, their branches and ports.
ramet compose <command>
Run docker compose on the current env, as in ramet compose logs -f web.
ramet checkpoint <label>
Set a return point on the env's data.
ramet restore <label>
Rewind the data to a checkpoint. Asks first.
ramet rm <name>
Remove an env and its data. Asks first.

ramet acts on the env of the directory you are in, as git does with branches. ramet --help lists the other commands, and the README documents all of them.

Addresses that follow the env

Each env runs on ports of its own. An address a browser opens, an OAuth callback or a CORS origin must carry that port. Name the port once, and write its variable where the address is: ramet never rewrites your files.

Name the port, then use it 
# .ramet.json
{ "ports": { "web": "proxy:80" } }

# compose.override.yml
services:
  app:
    environment:
      APP_URL: http://app.test${RAMET_PORT_WEB:+:$RAMET_PORT_WEB}

${RAMET_PORT_WEB:+:$RAMET_PORT_WEB} adds a colon and the port where the variable is set, and nothing elsewhere:

main
http://app.test, the project's usual port: the variable is unset, as without ramet.
feat-price
http://app.test:21000, the port of this env.

Before you start: write the variable where compose reads it, not in a .env the application loads by itself; a browser treats each port as another site; a Traefik reading the docker socket must be kept to its own env. The README covers each of them.

With AI agents

An env per task lets an agent work on real data without risk. Listings take --json, and a command that destroys data refuses to run without a terminal unless given --yes. The ramet skill teaches an agent the rest, including when to ask before passing it.
